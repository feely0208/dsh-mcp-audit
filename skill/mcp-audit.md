# MCP 服务安全

审计 MCP（Model Context Protocol）配置：未锁定的远端包、明文端点、可执行本地服务。

## 一、为什么 MCP 是新的攻击面

**MCP 服务拿到的权限，通常比一般插件大得多** —— 它能读写你的文件、执行工具调用、
访问你的账号。而它的配置往往：

- 散落在个人机器上（不在版本控制里）
- 用 `npx -y` 拉最新版（没有版本记录）
- 指向第三方二进制（难以审计）

**给 agent 装 MCP 服务，等于给它开门。**

## 二、它查什么

| 级别 | 项 | 为什么危险 |
|---|---|---|
| 🔴 高 | **`npx -y <包名>` 未锁版本** | 每次拉最新 → 上游投毒即刻执行，且无法回滚 |
| 🔴 高 | **明文 http:// 端点** | MCP 读写你的文件，明文可被中间人看到/改写 |
| 🟡 中 | **指向本地可执行文件/脚本** | 权限往往等于整个用户会话 |
| 🟢 低 | 仓库里找不到 MCP 配置 | 说明配置不在版本控制，没人审查过 |

## 三、怎么用

<cli 路径> --demo          # 看检出效果

## 五、边界

- **只审配置，不审服务本身**：MCP 服务的代码里有什么、会不会外发数据，本工具看不到。
- **锁定版本 ≠ 安全**：锁了版本只防「上游悄悄改」，防不了「这个包本来就是恶意的」。
- **配置位置各客户端不同**：Claude Desktop 用 `claude_desktop_config.json`，
  其它客户端可能用 `.mcp.json` / `settings.json`。本工具按常见路径找，
  **原生支持 .mcp.json / mcp.json / settings.json**。
- 与 [dsh-dep-audit](https://github.com/feely0208/dsh-dep-audit) 分工：
  那个查 npm 依赖的投毒面，这个查 MCP 服务的配置风险。
